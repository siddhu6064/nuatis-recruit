▶ PROMPT [Phase 2 · Batch 1 · Replit Agent]

CONTEXT
Brand new Replit project. Empty codebase. We are starting Phase 2 of 
the Nuatis Recruit build — an AI-native B2B SaaS recruiting platform 
for boutique tech staffing agencies. We are skipping any vendor 
provisioning beyond what Replit provides natively. Use Replit's 
built-in services for everything possible.

GOAL
A user can sign up via Replit Auth, automatically gets a workspace, 
invites a teammate, both log in, both see workspace members listed. 
Code is pushed to GitHub.

SCOPE — BUILD THIS

1. Turborepo monorepo with these workspaces:
   - apps/web — Next.js 14 (App Router) + TypeScript + Tailwind + 
     shadcn/ui (initialized via `npx shadcn@latest init`)
   - apps/ai — FastAPI (Python 3.11) + Pydantic v2 + Uvicorn (only a 
     /health endpoint at this batch)
   - packages/db — Drizzle ORM + Drizzle Kit migrations
   - packages/types — shared Zod schemas
   - packages/ui — shared shadcn components placeholder
   - packages/auth — auth abstraction layer (CRITICAL — see item 4)

2. Replit Postgres provisioned via the Database tab. Drizzle schema 
   in packages/db with these tables:
   - organizations (id uuid pk default gen_random_uuid(), name text 
     not null, slug text unique not null, plan_tier text default 
     'starter', created_at timestamptz default now())
   - workspaces (id uuid pk, organization_id uuid fk, name text, 
     settings_json jsonb default '{}', created_at timestamptz)
   - users (id uuid pk, workspace_id uuid fk, external_auth_id text 
     unique not null, external_auth_provider text not null default 
     'replit', email text not null, name text, role text check 
     (role in ('owner','recruiter','readonly')) default 'recruiter', 
     last_active_at timestamptz, created_at timestamptz)
   - audit_logs (id uuid pk, workspace_id uuid fk, user_id uuid, 
     action text, target_type text, target_id uuid, diff_json jsonb, 
     ip text, user_agent text, created_at timestamptz default now())

   Note the columns external_auth_id and external_auth_provider — 
   these are deliberately generic so we can swap auth providers later 
   without a schema migration.

3. Postgres Row-Level Security policies on workspaces, users, and 
   audit_logs filtering by current_setting('app.current_workspace_id'). 
   Implement a Postgres connection middleware that calls 
   `SET LOCAL app.current_workspace_id = $1` on every request, bound 
   to the authenticated user's workspace.

4. Replit Auth integrated for sign-in. CRITICAL ARCHITECTURE 
   REQUIREMENT — wrap all Replit Auth calls behind packages/auth:
   - packages/auth/src/index.ts exports these functions only:
     • getCurrentUser() → returns {id, email, name, workspace_id, 
       role} or null
     • requireAuth() → returns same, throws 401 if not authed
     • signOut() → ends the session
     • getInviteToken(workspaceId, email) → creates invite record
     • acceptInvite(token) → links new auth user to existing 
       workspace
   - Internally, this package uses Replit Auth's headers/cookies 
   - Pages and API routes in apps/web import from packages/auth ONLY. 
     They must NEVER import @replit/auth directly. This makes the 
     future swap to Clerk a one-file change.
   - Add a comment block at the top of packages/auth/src/index.ts:
     "// AUTH ABSTRACTION — swap implementation here to change 
     providers (Replit Auth → Clerk). Pages/routes consume these 
     exports only."

5. On first sign-in via Replit Auth, atomically create organization 
   + workspace + user records with role='owner' if no user record 
   exists for that external_auth_id. Use a Postgres transaction.

6. Invite flow: at /settings/members, owners can generate an invite 
   link tied to a workspace_id + invitee email. Store invites in an 
   `invites` table (id, workspace_id, email, token unique, expires_at, 
   used_at). Invitee clicks link → signs in via Replit Auth → invite 
   token consumed → user added to workspace as role='recruiter'.

7. Three pages in apps/web:
   - / — redirects to Replit Auth sign-in if not authed, /dashboard 
     if authed
   - /dashboard — shows "Welcome, [user.name]" + workspace member 
     list with roles and last_active_at
   - /settings/members — owner-only; "Generate invite link" form + 
     member list with role dropdowns + Remove button

8. FastAPI service in apps/ai with only:
   - GET /health → returns {"status": "ok"} (200)
   - CORS configured to allow apps/web origin only
   No AI features yet. No /test-error. No other endpoints.

9. Top navigation in apps/web: workspace name on the left, user 
   avatar dropdown on the right with "Settings" and "Sign out".

10. GitHub integration: initialize git, create initial commit, push 
    to https://github.com/siddhu6064/nuatis-recruit (the empty 
    private repo I created). Configure the Git pane in Replit so I 
    can push subsequent batches with one click.
